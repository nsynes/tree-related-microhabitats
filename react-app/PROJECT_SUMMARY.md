# Tree Microhabitat & Species Explorer - Project Summary

## Overview

A lightweight React application for exploring relationships between tree microhabitats (TreMs) and associated species. This app was migrated from R-Shiny to React for better UX, easier deployment, and no server requirements.

## Project History

### Phase 1: R-Shiny Development (Archived)
- Initial development in R-Shiny with modular architecture
- Features: Habitat filtering, species cards, caching system
- Config-driven filters using YAML
- Located in: `archived/`

### Phase 2: React Migration (Current)
**Why React?**
- Client-side only (no server needed)
- Better UX with instant interactions
- Easier deployment (static hosting on S3)
- Modern component architecture
- Lightweight bundle (< 200KB target)

## Tech Stack

**Core:**
- **React 18** - UI framework
- **Vite** - Build tool (fast, excellent tree-shaking)
- **Zustand** - State management (1KB!)

**No UI Library** - Pure CSS for minimal bundle size

## Data Flow

1. **Build Time:**
   ```
   CSV → process-data.js → species.json (with pre-computed habitats)
   ```

2. **Runtime:**
   ```
   Load species.json → Zustand store → React components → User filters → Instant UI update
   ```

## Development Workflow

### Install Dependencies
```bash
cd react-app
npm install
```

### Run Development Server
```bash
npm run dev
```
This will:
1. Process CSV data → JSON
2. Start Vite dev server
3. Open http://localhost:5173

### Build for Production
```bash
npm run build
```
Output: `dist/` folder ready for S3 deployment

### Update Data
1. Update CSV file: `../data/Tree_TreMs_species spreadsheet.csv`
2. Run: `npm run process-data`
3. Rebuild: `npm run build`

## Data Schema

### Species Data (species.json)
```json
{
  "id": 1,
  "scientificName": "Quercus robur",
  "commonName": "English Oak",
  "class": "Aves",
  "family": "Picidae",
  "habitats": ["tree_oak", "woodland", "ancient", "trunks", ...]
}
```

### Filter Config (config.json)
```json
{
  "id": "tree_oak",
  "label": "Oak",
  "column": "Tree species",
  "searchTerm": "oak"
}
```

## Key Design Decisions

1. **Build-time processing** - Better performance, smaller runtime bundle
2. **Pure CSS** - Avoid MaterialUI bloat, custom styling
3. **Zustand over Redux** - Lightweight (1KB), perfect for this scale
4. **CSS show/hide filtering** - Instant UI updates, no re-renders
5. **Empty state messaging** - Better UX, guide users
